Video HTML: animação como função do tempo

Este documento define o contrato que todo template de vídeo deve seguir para funcionar no Motion Studio. A regra que governa tudo: o template nunca tem relógio próprio. O player informa o tempo; o template desenha exatamente aquele instante.

00:00

O que é um Video HTML

Um Video HTML é um único arquivo .html autocontido (CSS e JS inline) que descreve uma animação com duração fixa. Ele é usado em dois ambientes com o mesmo mecanismo:

Preview (editor): o arquivo roda num iframe. A timeline do editor envia o tempo atual e o template renderiza aquele instante.

Export (servidor): um Chromium headless com relógio virtual captura frame a frame. Para cada frame, o renderizador chama Motion.seek(t) com o tempo exato daquele frame e fotografa o resultado. Os frames viram um MP4 via FFmpeg.

Consequência central: a animação precisa ser determinística. Chamar seek(2.5) deve produzir o mesmo pixel sempre — não importa se foi chamado antes seek(0), seek(4), ou nada. Sem estado acumulado, sem dependência de tempo real.

Contrato obrigatório: window.Motion

O template deve expor um objeto global window.Motion com esta interface:

MembroStatusDescrição
Motion.configOBRIGATÓRIO Objeto com fps (número, ex. 60), durationInSeconds (número, ex. 5) e totalFrames (= fps × durationInSeconds). Define a duração nativa do clip na timeline.
Motion.seek(t)OBRIGATÓRIO Recebe o tempo em segundos (float, 0 → durationInSeconds) e desenha exatamente aquele instante. Deve ser pura e idempotente: mesma entrada, mesmo visual, em qualquer ordem de chamada. Clampeie internamente valores fora do range.
Motion.renderFrame(f)OBRIGATÓRIO Mesma coisa endereçada por índice de frame (inteiro). Implementação canônica: seek(f / config.fps).
Motion.whenReady()OBRIGATÓRIO Retorna uma Promise que resolve quando fontes e assets terminaram de carregar (ex.: document.fonts.ready). O player espera por ela antes do primeiro frame — evita capturar texto com fonte fallback.
Motion.init()OPCIONAL Preparação única (medições, criação de elementos). Se existir, o player chama uma vez antes do primeiro seek. Deve ser seguro chamar mais de uma vez.

Tokens literais exigidos pelo validador

O servidor valida o arquivo por presença textual. Estes identificadores precisam aparecer literalmente no código (a implementação natural do contrato já os inclui):

Regras de determinismo

Permitido

  • Calcular todo estado visual dentro de seek(t) com funções de easing puras
  • Manipular style, transform, opacity, atributos SVG, canvas 2D/WebGL — desde que redesenhado por seek
  • Math.sin/cos e ruído derivados de t (pseudo-aleatório com seed fixa)
  • Google Fonts via <link>; aguardar em whenReady()
  • Imagens locais com caminho relativo assets/nome.png
  • Bibliotecas externas via CDN https com versão fixa (three.js, GSAP, anime.js, Lottie, PixiJS, D3…) — sempre dirigidas por seek(t)
  • 3D e WebGL: modelos glTF/GLB, texturas, shaders, pós-processamento — renderizados dentro de seek(t)
  • Imagens, modelos e dados por URL https (com CORS), carregados antes de whenReady() resolver

Proibido

  • requestAnimationFrame ou setInterval/setTimeout autônomos dirigindo a animação
  • Date.now() / performance.now() como fonte de tempo da animação
  • Math.random() sem seed (cada frame sairia diferente entre preview e export)
  • transition CSS dependente do estado anterior (seek fora de ordem quebra)
  • Tags <video>/<audio> dentro do template (mídia entra como clip separado na timeline)
  • Requests de rede depois que whenReady() resolveu (o export fotografa frames sem esperar downloads)
  • Loops próprios das bibliotecas dirigindo a animação: renderer.setAnimationLoop, autoplay:true, timelines tocando sozinhas, clock.getDelta()
Sobre CSS @keyframes: o player consegue sincronizá-los externamente, mas o método preferido é sempre computar o estado em seek(t) via JS. Se usar keyframes, aplique animation-play-state: paused e nunca dependa deles para timing crítico.

Bibliotecas externas, efeitos e 3D

Preview e export carregam scripts, módulos ES, modelos e texturas de CDNs públicas. Use URLs https com versão fixa de cdn.jsdelivr.net, cdnjs.cloudflare.com ou unpkg.com (evite esm.sh/skypack: usam imports absolutos que quebram). A regra continua a mesma: a biblioteca nunca toca sozinha — seek(t) posiciona tudo.

  • three.js (3D): <script type="importmap"> apontando "three" para https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js e "three/addons/" para …/three@0.160.0/examples/jsm/; código em <script type="module">. new THREE.WebGLRenderer({ antialias:true, alpha:true, preserveDrawingBuffer:true }), setPixelRatio(1), setSize(W,H). Em seek(t): posicione câmera/objetos a partir de t e chame renderer.render(scene, camera). Nunca setAnimationLoop nem Clock. Crie o renderer dentro de try/catch: sem WebGL no navegador (aceleração por hardware desligada), deixe renderer = null, pule o render 3D no seek e mantenha textos/2D animando — o erro nunca pode impedir que window.Motion seja definido.
  • Modelos glTF/GLB: GLTFLoader().loadAsync(url) dentro da Promise de whenReady(). Animações do modelo: mixer = new THREE.AnimationMixer(gltf.scene), mixer.clipAction(clip).play() e em seek(t) use mixer.setTime(t) (determinístico). Modelos de exemplo: https://cdn.jsdelivr.net/gh/KhronosGroup/glTF-Sample-Models@master/2.0/<Nome>/glTF-Binary/<Nome>.glb (Duck, Fox, BoxAnimated, DamagedHelmet, Avocado…). Sem modelo adequado, construa a cena com geometrias procedurais.
  • Shaders / efeitos WebGL: ShaderMaterial com uniforms.uTime.value = t; pós-processamento (EffectComposer, bloom) chamando composer.render() dentro de seek.
  • GSAP: <script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.5/gsap.min.js">; const tl = gsap.timeline({ paused:true }) e seek(t) { tl.seek(t, false) }.
  • anime.js: autoplay:false e anim.seek(t * 1000). Lottie: lottie.loadAnimation({ autoplay:false, renderer:'svg', path:url }), aguarde 'DOMLoaded' no whenReady e use anim.goToAndStop(t * 1000, false).
  • Canvas 2D / PixiJS / partículas: calcule cada partícula como função de t e de uma seed fixa (PRNG tipo mulberry32), ou simule a física do zero até t com passo fixo. Nunca acumule estado entre chamadas de seek.
  • Efeitos CSS/SVG: filter, backdrop-filter, mix-blend-mode, máscaras, feTurbulence/feDisplacementMap com atributos atualizados em seek. Use com moderação: blur grande em centenas de elementos deixa preview e export lentos.
whenReady() é o portão do export: ele só pode resolver depois que bibliotecas, modelos, texturas e fontes terminaram de carregar (e de preferência depois de um seek(0)). O export espera até ~45 s; o que chegar depois disso sai faltando nos primeiros frames.

Efeitos sonoros (opcional): Motion.sfx

Só quando o pedido incluir sons. O clipe declara os efeitos e o editor os sintetiza numa faixa de áudio sincronizada (com waveform, volume e export) — o HTML continua sem nenhum áudio próprio.

window.Motion = {
  config: CONFIG,
  sfx: [
    { t: 0.15, type: 'whoosh' },            // entrada do título
    { t: 0.90, type: 'pop', gain: 0.6 },    // ícone surgindo
    { t: 2.00, type: 'riser', dur: 1.2 },   // tensão até a revelação…
    { t: 3.20, type: 'impact' },            // …que acontece aqui
  ],
  seek, renderFrame, whenReady,
};
  • t: segundos do clipe (mesmo relógio de seek). Opcionais: gain 0–1 (padrão 0.8), pitch (1 = normal), pan −1…1, dur em segundos.
  • Sintetizados (type): whoosh, swipe, riser, impact, bass, pop, click, tick, typing, ding, chime, success, notification, coin, glitch.
  • Biblioteca sfxkit (CC0, 320 sons neutros): sound: "sfxkit/<som>", ex.: "sfxkit/whoosh-medium-soft", "sfxkit/pop-small-in", "sfxkit/impact-medium-soft". O editor alinha o ponto de ataque do som ao t da deixa (t = instante da tela). Funciona com qualquer pacote; prefira-a para movimento, impacto, dados e notificações.
  • Biblioteca externa CC0 (sound: "<pacote>/<som>", ex.: "cinematic/achievement", "glass/notification"): sons reais gravados, 12 pacotes de estilo × 78 sons. O catálogo completo vem no pedido quando os sons estão ativados; use um único pacote no vídeo inteiro.
  • Um som por acontecimento visual relevante, alinhado ao instante exato do movimento; 3 a 10 por clipe costuma bastar.
  • Proibido: <audio>, WebAudio, Tone.js ou arquivos de som — o editor não os captura no export.

Layout, resolução e transparência

html e body devem ter o tamanho exato da resolução do projeto em pixels (ex.: width:1080px; height:1920px) com overflow:hidden e margin:0. O player escala o template para o box do clip na timeline — nunca use unidades de viewport (vw/vh) como base do layout.

Fundo: se o template é um overlay (título, lower-third, sticker), use background: transparent para compor sobre os clips das tracks inferiores. Se é uma cena de fundo, defina uma cor/gradiente sólido.

Empilhamento: na timeline, tracks superiores cobrem as inferiores. O template não controla isso — apenas garanta que a transparência esteja correta.

Checklist antes de entregar

  1. Arquivo único: CSS e JS do clipe inline, sem bundlers. Bibliotecas externas só via CDN https com versão fixa (<script src> clássico ou importmap + type="module").
  2. window.Motion expõe config (com fps, durationInSeconds, totalFrames), seek, renderFrame e whenReady.
  3. seek(t) é pura: chamar com qualquer t, em qualquer ordem, produz sempre o mesmo visual. Teste mental: seek(3); seek(0.5); seek(3) — os dois seek(3) são idênticos?
  4. Zero rAF/setInterval autônomos, zero Date.now(), zero Math.random() sem seed.
  5. html,body no tamanho exato da resolução, overflow:hidden, fundo transparente se for overlay.
  6. Fontes aguardadas em whenReady() (document.fonts.ready).
  7. Valores clampeados: seek(-1) e seek(999) não quebram nem geram estado inválido.
  8. Sem <video>/<audio> embutidos; todo asset externo (lib, modelo, textura, fonte) carregado antes de whenReady() resolver.
  9. Bibliotecas e 3D sem loop próprio: nada de setAnimationLoop, autoplay ou timeline tocando sozinha — só seek(t).
